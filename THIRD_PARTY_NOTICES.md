# Third-party notices

lib-image contains no third-party code. Formats follow their public
specifications: RFC 1950 (zlib), RFC 1951 (DEFLATE), the PNG specification
(ISO/IEC 15948, W3C PNG Third Edition) and JPEG (ITU-T T.81 | ISO/IEC
10918-1, JFIF, Adobe's APP14 and the ICC's APP2 conventions). The format
tables (DEFLATE's length and distance bases and code length order; JPEG's
zigzag order and the Annex K example quantization and Huffman tables) are
interoperability constants from those specifications.

`crates/exr/src/compression/piz.rs` and `pxr24.rs` implement OpenEXR's
PIZ and PXR24 algorithms (the wavelet, the Huffman code layout, the 24-bit
float rounding), written for this library from OpenEXR's description and
behaviour; OpenEXR's BSD-3-Clause notice is retained in
`crates/exr/LICENSE-OpenEXR` (Copyright Contributors to the OpenEXR
Project).

The Paeth predictor's threshold form in `crates/png/src/filter.rs` is an
algebraic identity of the PNG specification's predictor, checked against
it for every input by the tests.

## Test fixtures

- `crates/exr/tests/fixtures/openexr` are written by OpenEXR's Python
  bindings from a synthetic pattern (`tools/exr_oracle.py fixtures`).
- `crates/png/tests/fixtures` and `crates/jpeg/tests/fixtures/reference`
  are generated by the scripts in `tools/` with Python's zlib and Pillow.
- `crates/jpeg/tests/fixtures/*.jpg` and `icc/icc-*.jpg` come from
  luce-jpeg (our own repository): synthetic pictures encoded by Pillow,
  libjpeg-turbo's cjpeg and TurboJPEG (`tests/make_fixtures.py`,
  `tests/make_icc_fixtures.py` there). `icc/expected.txt` is what
  libjpeg-turbo's `jpeg_read_icc_profile` joins from each.
- `crates/jpeg/tests/fixtures/icc/ladybird-icc-v4.jpg` and
  `ladybird-gradient-empty-icc.jpg` are from Ladybird's test inputs
  (BSD 2-Clause License, `crates/jpeg/tests/fixtures/icc/LICENSE-ladybird`).
